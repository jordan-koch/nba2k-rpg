### goals

- Establish the HTTP seam: a FastAPI application in its own source package under src/, serving a health endpoint whose payload is produced by the backend, so items 1.2-1.11 have something to attach an endpoint to.
- Establish the frontend seam: a React + TypeScript SPA on Vite under app/, in strict mode, rendering one page that fetches the health endpoint across a real network boundary — proving the seam rather than mocking it.
- Prove and protect the dependency direction DESIGN.md:106-109 asserts: rpg_api imports rpg_core (concretely, the health payload's version comes from rpg_core.__version__), and rpg_core imports no web framework — enforced by a structural test, not by convention.
- Give 'run the app' two honest answers: a hot-reload development mode (Vite dev server proxying /api to uvicorn) and a single-process mode where FastAPI serves the built SPA out of app/dist.
- Extend the repo's existing quality posture to the new half of the codebase: a separate CI job that runs Node install, typecheck, lint, and build, and that is actually a REQUIRED status check rather than an advisory one.
- Land the dependency bookkeeping correctly in one change: fastapi + uvicorn in pyproject.toml [project].dependencies with uv.lock regenerated (ci.yml:34 runs `uv sync --locked`, which hard-fails on a stale lock), a committed app/package-lock.json, and the npm ecosystem entry .github/dependabot.yml:30 is holding a slot for.
- Make the run story discoverable: ops/README.md gains the Node toolchain and the two run modes alongside the existing uv section; README.md's Setup and project map stop describing a repo with no application.

### risks

- Branch-protection drift is the sharpest risk here. ops/branch-protection.json:4 lists job DISPLAY names, and the file is inert until re-applied to GitHub with `gh api -X PUT` (ops/README.md:11-14) — an action .claude/settings.json puts in the `ask` list, i.e. the user's. Editing the JSON and forgetting the re-apply produces a repo where the frontend job runs, fails, and does not block the merge, with nothing anywhere reporting the discrepancy.
- tests/test_no_leaks.py scans .json/.ts/.tsx/.css/.html by suffix (lines 38-55) and its docstring's claim that 'lockfiles are skipped' holds for uv.lock (suffix .lock) but NOT for app/package-lock.json (suffix .json). Inferred, not measured: npm lockfileVersion 3 entries carry version/resolved/integrity/license/funding and rarely an email, so the guard will probably pass — but this must be run before the lock is committed, and if it trips, the correct fix is an ALLOWED entry with a written reason rather than weakening the regex that protects a public repo.
- mypy strict (pyproject.toml:63) includes disallow_untyped_decorators. FastAPI ships py.typed so route decorators are typed, but unannotated handler return types and any use of an untyped third-party helper will fail the build. The failure mode to avoid is a per-module mypy override quietly carving rpg_api out of strict mode on its first day — which would leave the API half of the codebase permanently weaker than the domain half, the exact asymmetry this item exists to prevent on the frontend side.
- This item chooses conventions eleven later items inherit — package name, route prefix, error-response shape, where DTOs will live, how the frontend talks to the API — with zero domain content to test them against. Over-deciding blind is as expensive as under-deciding: intake was right to defer routing and the shared type contract, and the same discipline should apply to anything that looks like a framework.
- npm supply chain in a public repo. `npm ci` for a Vite/React toolchain executes install scripts (esbuild fetches a platform binary), pulling a transitive tree far larger than the four-package Python dev group. The mitigations available are the committed package-lock.json and the dependabot npm entry; there is no version of this item that avoids the exposure, and the honest position is to note it rather than claim it is handled.
- Windows/PowerShell friction in npm scripts. `&&` chaining and POSIX inline env-var prefixes in package.json scripts fail on this machine's default shell. Keeping every script a single command avoids it; discovering it during implementation on Linux CI (which passes) and only breaking locally is the likely path.
- Two dependency-lock disciplines now exist with different commands (`uv lock` / `npm install`) and different CI enforcement (`uv sync --locked` at ci.yml:34 / `npm ci`). ops/README.md:54-57 documents the uv rule sharply; the Node rule needs the same sharpness or a stale package-lock.json becomes an intermittent CI failure nobody can attribute.
- .gitignore:63 has a blanket `build/` rule under the Python section, which matches a directory named build at ANY depth. Not a problem for this item (Vite outputs to dist/, already ignored at line 68) but it will silently shadow the `build/build-*.py` builder pattern CLAUDE.md:171-174 says Phase 2 should follow. Out of scope here; worth recording so it is found before item 2.1 rather than during it.
- Scope-to-ceremony mismatch. ROADMAP.md:165 sizes 1.1 as M and does not mark it ★; ROADMAP.md:121-122 says unmarked items should skip straight to a plan or straight to work. Every enhancement above is individually cheap, and taking all of them turns a day's item into a week's. The gate should tier deliberately.

### risks

- THE HEADLINE RISK — adding the web job to `ops/branch-protection.json` does nothing until the user re-applies it. `required_status_checks.contexts` is `["Lint, types, tests", "Secret scan"]` (ops/branch-protection.json:2-5) and applying the file requires `gh api -X PUT ... --input ops/branch-protection.json` (ops/README.md:11-14) — an `ask`-gated permission (.claude/settings.json:8) and a repository-settings change that ops/README.md:3-5 states is deliberately user-run. Until that command is run, a PR with a failing frontend job merges green. This must be surfaced as an explicit user action in the handoff, not buried in the plan.
- `tests/test_no_leaks.py` will scan the new frontend files and can fail on things nobody expects. `.json`, `.ts`, `.tsx`, `.js`, `.mjs`, `.css`, `.html` are all in `TEXT_SUFFIXES` (lines 38-55), and only `tests/test_no_leaks.py` and `.env.example` are in `ALLOWED` (lines 32-35). Two concrete tripwires: (a) a `package.json` with `"author": "Name <<email-redacted>>"` fails `test_no_email_addresses`; (b) the file's own comment says 'Binary and lockfiles are skipped' — that is true of `uv.lock` (suffix `.lock`, not in the set) but FALSE of `package-lock.json`, which ends in `.json` and therefore IS scanned. Low probability of an actual hit (npm lockfiles carry registry URLs, not local paths) but the comment is now inaccurate and should be corrected in the same change.
- mypy strict over FastAPI. `strict = true` plus `warn_unreachable` (pyproject.toml:61-65) with `files = ["src", "tests"]` will type-check the new package automatically — which is correct, but route decorators and dependency injection are a known friction point under `disallow_untyped_decorators`. Budget for either explicit return annotations everywhere or a narrowly-scoped per-module override, and prefer the former; a blanket relaxation would make the API the loose half of the Python side.
- Forgetting `[tool.hatch.build.targets.wheel] packages` (pyproject.toml:30-31, currently `["src/rpg_core"]`). `uv sync` installs the project, so an unlisted second package produces an installed environment where the API is not importable — while `pytest` still passes locally because `pythonpath = ["src"]` (pyproject.toml:73) puts it on the path anyway. That divergence between the test path and the install path is a genuinely confusing failure.
- Forgetting the coverage target. ci.yml:47 runs `--cov=rpg_core`; left unchanged, every line of new API code is invisible to coverage and the number reported stays reassuringly high while the new package is entirely unmeasured.
- Windows/Node IPv6 resolution. A Vite proxy targeting `http://localhost:8000` can resolve to `::1` on Windows while uvicorn binds `127.0.0.1`, producing an ECONNREFUSED that looks like the backend is down when it is running fine. Pin the proxy target to the IPv4 literal.
- Process lifecycle in the one-command launcher. Ctrl+C in PowerShell against a Node process-runner that spawned `uv run uvicorn` can leave the Python child orphaned and holding the port, so the next `npm run dev` fails with EADDRINUSE. Verify signal propagation on Windows specifically, or document the manual cleanup.
- Adding an ADR without indexing it turns the build red: `test_every_adr_is_listed_in_the_index` (tests/test_repo_structure.py:113-121) and `test_adr_numbers_are_unique_and_contiguous` (lines 124-133) both bite. The ADR file and its `docs/decisions/README.md` row must land together.
- CLAUDE.md has a hard 200-line budget checked by the update-docs gate (`.claude/skills/update-docs/SKILL.md`:76-78). Adding `app/` and the new source package to its project map means something else gets cut, not just appended.
- Package-name churn is cheap now and annoying later, exactly as the request says: the name binds `[tool.mypy] files`, the hatch wheel `packages` list, ci.yml's `--cov` flag, the console-script entrypoint, the layering test's deny-list, and every import in items 1.2-1.11. Decide it explicitly rather than letting the first file created decide it.
- The frontend has no lockfile-parity gate equivalent to `uv sync --locked`. Use `npm ci` (which fails on a `package.json`/`package-lock.json` mismatch) rather than `npm install` in CI, or the frontend quietly loses the guarantee the Python side enforces.
- Scope-creep pressure is real here and I am the ambitious lane: the enhancement list above is long, and roughly twenty of those items are individually cheap while collectively being more surface area than the feature itself. The tiering must be genuinely disposed by the user, not accepted wholesale — ROADMAP.md sizes this item `M` (a day or so), and the greedy version as written is comfortably larger than that.
- UNCONFIRMED and worth verifying before the plan: whether GitHub's protection API accepts the updated JSON unchanged (the file has not been re-applied since Phase 0), and whether the repository owner/name in the ops/README.md example command still matches the actual remote.

### risks

- **Silent-green merges — the highest-severity risk in this item.** `ops/branch-protection.json:4` lists contexts `["Lint, types, tests", "Secret scan"]`, matched by CI job *display name*. A new job is advisory until its name is added there *and* the user re-applies the config via `gh api -X PUT` (`ops/README.md:11-14`). An agent cannot do the second half — `gh api *` is in the `ask` list of `.claude/settings.json`. The symptom is a PR merging with a red frontend job and nothing complaining. Mitigations: the guard test in core scope for the tracked half, and a loudly-flagged user-run acceptance criterion for the applied half.
- **Wheel-packages omission fails only at runtime, never in CI.** `[tool.hatch.build.targets.wheel] packages = ["src/rpg_core"]` (`pyproject.toml:31`) controls what `uv sync` installs, but `[tool.pytest.ini_options] pythonpath = ["src"]` (line 73) puts `src/` on the path for tests regardless. So if `src/rpg_api` is left out of the packages list, every test passes, CI goes green, and `uv run uvicorn rpg_api.main:app` fails with `ModuleNotFoundError` on the user's machine. This is the sneakiest failure in the whole item because the test suite structurally cannot see it.
- **Stale `uv.lock`.** `.github/workflows/ci.yml:34` runs `uv sync --locked`, which hard-fails rather than re-resolving. Adding FastAPI without running `uv lock` in the same commit turns every subsequent PR red until fixed. The npm mirror is identical and equally easy to hit: `npm ci` requires `package-lock.json` to agree with `package.json`, so a hand-edited `package.json` fails CI exactly the way a hand-edited `pyproject.toml` does.
- **Mounting a missing `app/dist/`.** *Inferred:* Starlette's `StaticFiles` raises at construction time when the directory does not exist, which means a fresh clone that has not run `npm run build` gets an import-time traceback instead of an app. This is Open Question 2 and it is the first thing a cold agent trips on. It is also why the dist path must be injectable — a module-level `Path` constant makes both branches untestable without a real directory, and the untested branch is the one everyone hits first.
- **Windows/Linux parity in npm scripts.** The user's daily shell is PowerShell (*measured* from the environment; `research/tools/iff.ps1` corroborates) while CI is `ubuntu-latest`. Any `package.json` script using `&&`, `rm -rf`, `cp`, or POSIX quoting works in CI and fails locally — PowerShell 5.1 does not have `&&` at all. Keep every script to a single command invocation with no shell operators.
- **Node toolchain drift between local and CI.** Local is node v24.15.0 / npm 11.12.1 (*measured*); CI will run whatever major the workflow pins. A lockfileVersion or transitive-resolution difference between npm majors produces a lockfile that installs locally and fails `npm ci` in CI, with an error that points at a package rather than at the version skew. The mitigation is pinning the CI major to the installed one and saying so in `ops/README.md`.
- **`tests/test_no_leaks.py` now scans frontend files.** Its `TEXT_SUFFIXES` set (lines 38-55) includes `.ts`, `.tsx`, `.js`, `.mjs`, and `.json`, so `vite.config.ts`, `tsconfig.json`, and `package-lock.json` all enter scope. Left unchanged, `rpg_api` is simply absent from the report — not a failure (no `fail-under` is configured), just a number that quietly stops describing the codebase.
